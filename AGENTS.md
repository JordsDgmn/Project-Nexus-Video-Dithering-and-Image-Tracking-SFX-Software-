## Claim and release work

1. Use your stable agent name. Read TASKS.md and HANDOFF.md to see active owners and exact paths. A claim covers every file you intend to edit, including tests and shared configuration.
2. The user assigns the ownership grants in TASKS.md. Before editing, confirm your grant and check the workspace again. If the grant is missing, paths overlap, or an unexpected edit appears, stop work on those paths and ask the user to resolve ownership. Silence and stale timestamps never transfer ownership.
3. Only the current documentation coordinator edits TASKS.md, HANDOFF.md, and DEVLOG.md. Other agents write updates in their individually assigned Markdown files. Read-only review can run while an owner edits.
4. Before handoff, record exact paths changed, checks run and their results, known gaps, and the proposed next action. The coordinator records release and the next grant before the receiving agent edits those paths.

Use D:\Project-Nexus as the project root. Keep project files and generated artifacts inside it. Preserve existing user changes. Request approval for installs or other changes outside the project. Use synthetic footage or user-approved samples and keep source video intact.
